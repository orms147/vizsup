# vizsup — Chinese→Vietnamese video subtitle + dubbing tool

Personal, local tool. Paste a **Douyin / Bilibili** URL → download → generate **Vietnamese subtitles** → **edit them (human gate)** → **Vietnamese voiceover (lồng tiếng)** → render a final MP4. Source videos may or may not have hardcoded (burned-in) Chinese subtitles.

Decision record and tool rationale: **[docs/research.md](docs/research.md)**. Pipeline data flow: **[docs/architecture.md](docs/architecture.md)**. Provider matrix: **[docs/providers.md](docs/providers.md)**.

## Pipeline (each stage is resumable; state on an absolute timeline)

`input → download → hardsub-detect → (OCR | ASR) → translate(2-pass) → ⛔HUMAN EDIT GATE → TTS → fit+mix → render`

- **download** — `yt-dlp` (cookies, domain-routed). Fallback: BBDown (Bilibili), TikTokDownloader (Douyin).
- **split (long videos)** — > 45 min and "Chia video dài" on (default): `pipeline/split.py` cuts ~30-min parts with ffmpeg's segment muxer at keyframes inside voice gaps (VAD, silencedetect fallback; stream copy, exact). Each part is a normal job (`metadata.group`); the parent folder keeps `group.json` and is not a project. Parts run through the queue (review part 1 while part 2 runs), share the first part's brief, merged glossary suggestions and the subtitle style; `split.join` concatenates the rendered parts (copy, or re-encode when params differ) + a shifted vi.srt. Renders are pinned to the source length (`-t`, dub `apad`) so joins don't drift.
- **hardsub-detect** — RapidOCR over ~16 sampled bottom-third crops; enough frames with recognized Chinese text ⇒ hardsubs → OCR path, else ASR ("Tự động" in the GUI, `--source auto` in the CLI; manual override always available).
- **OCR** (hardsubs present) — RapidOCR (ONNX PP-OCRv5+) frame sampling → CN SRT with per-cue confidence (`ocr_report.json`) → optional LLM proofread (suspect lines only). Frames stream through a pipe (no PNG dump), progress/ETA, resumable via `ocr_frames.json`; Engines are providers (`providers/ocr/`): `rapidocr` local (default; on Windows the GPU via `onnxruntime-directml` — no CUDA, output identical to CPU, ~2.7× faster, ONE worker since parallel DirectML sessions segfault; CPU ~0.25–0.5 s/frame; opt-in "OCR nhanh" = 1 frame/s, 2× faster, fine for films, misses sub-second vlog captions) or `vision_llm` — an OpenRouter vision model (role `ocr`, qwen3.7-flash) reads numbered strips of the text band, opt-in because it uploads them; far more accurate on stylised captions, ~$0.1 / 30 min per 3-hour video (docs/providers.md).
- **ASR** (no hardsubs) — default **cloud** `audio_llm`: Qwen-Omni (OpenRouter) writes the transcript, Whisper word timestamps (cloud, or local faster-whisper if installed) time it. Local engines (`faster_whisper`, `funasr_aligned`) are optional extras and NOT installed on this machine (removed 2026-10-01). Benchmark: `docs/providers.md`. Under music Whisper collapses word times: with an NVIDIA GPU a Demucs speech stem (`pipeline/separate.py` → `vocals.wav`) is what gets timed and VAD'd (opt-out `--no-vocal-timing`); collapsed clusters are re-asked on just that stretch; an empty Whisper answer is retried and never cached. `retime` re-groups lines by text and maps VI lines by an alignment DP.
- **timing pass** (`pipeline/timing_pass.py`, option "Chỉnh thời gian chuẩn", editor ··· action) — Netflix/Aegisub-style: 2-frame minimum gap, chains gaps < 0.5 s, min 20 frames, optional scene-cut snap.
- **snap ("tự canh lời")** — local Silero VAD (`pipeline/vad.py`, ONNX, model downloaded once to `storage/_models`) → each fresh CN cue edge moves to the nearest voice start/stop of its OWN voice within ~1 s (`pipeline/snap.py`). Runs before translate (opt-out: GUI option / `--no-snap`); editor: A / Shift+A, one undo step. Singing under loud music fools VAD; `vad.voice_spans` fills those gaps from the saved Whisper word track (`asr_words.json`; old jobs: "Đo lại thời gian" fetches it).
- **translate** — two-pass, provider-pluggable: CN-native draft → frontier refine. Strip timecodes locally; batch ~50 lines with context + glossary + video meta.
- **series ("Bộ phim", `pipeline/series.py`)** — profiles in `storage/_series/<slug>/series.json` (glossary, characters + xưng hô, brief, style, render settings, pronounce); a project links via `series_link.json` (auto from 《…》 in the title, or picked in input / `--series`). Inherited at run start (glossary layer suggested < series < global < project; series sheet + the previous approved episode's last 8 lines in the prompt); learned on approval (terms still in the approved vi.srt, earlier wins) and from the first real render; names + xưng hô: the next episode's run reads the newest unread approved episode once (`pipeline/cast.py`, one "brief"-role call → characters with `auto: true`, the owner's rows win, `cast_learned.json`) and the episode brief gets the series sheet as fixed input. Dialog `desktop/series_dialog.py`.
- **vi-lint ("Soát lỗi tiếng Việt", `pipeline/vi_lint.py`)** — after translate, before AI review: typography auto-fix only (…, spaces around punctuation, quotes, doubled function words); flags han / num / latin / pron / term through `review.cue_issues`. Option + editor ··· action; `--no-vi-lint`.
- **voice guess (`pipeline/voices.py`)** — per-line "m"/"f" from median F0 into overrides.json (`voice` key, part of the approved revision); render option "Giọng theo nhân vật (nam/nữ)" (default OFF) picks the provider's female / male voice per line. Opt-in: Tùy chọn "Đoán giọng nam/nữ" / `run --voice-guess` (the owner dubs with one voice). Per-video threshold (widest F0 gap 150–260 Hz), Demucs speech stem when there is no vocals.wav (GPU only; `VIZSUP_NO_AUTO_SEPARATE=1` in tests).
- **HUMAN EDIT GATE** — PySide6 timeline+table editor (desktop/). **Nothing downstream runs until the user approves.** Approval is a hash of the revision files (`pipeline/approval.py`); opening an approved project must never change its revision files (vi.srt, style.json, style_overrides.json, commentary.json, overrides.json) — 83c808c. Editor extras: compact list ("Gọn"/"Rộng"), overview strip, safe-zone overlay (`widgets/safe_zones.py`), CSV export/import (`pipeline/subcsv.py`), edge snapping on drag.
- **TTS** — provider-pluggable; local **VieNeu** (`providers/tts/vieneu.py`, ONNX/CPU, free; owner's voices Quốc Tuấn / Trúc Ly / Ngọc Huyền / Adam bựa; install `--no-deps` so onnxruntime-directml stays) is listed next to any provider's voices as `vieneu:<name>` (`registry.split_voice` / `voice_choices`); edge also offers 4 multilingual female voices that read Vietnamese (Vivienne, Thalita, Emma, Seraphina). Default edge-tts vi-VN (needs edge-tts ≥ 7.3.1 — Microsoft refused 7.2.8 with HTTP 403 on 2026-10-16; Settings → "Cập nhật edge-tts"). edge-tts answers "no audio" at random (~40 % some nights): each line retries alone (0.3/1/2 s) before the shared cooldown; 6 lines in flight. Text is spoken through `pipeline/speak.py` (numbers, units, abbreviations + `pronounce.json`, global and per project); the TTS cache key is the spoken text.
- **commentary (F-4)** — the user's own notes (`pipeline/commentary.py`, `commentary.json`, editor tab "Bình luận"): text in a voice other than the dub's or their own recording; "pause" freezes the picture (ONE `tpad` per piece — a second chained tpad drops its padding) and shifts everything after it, "over" speaks over the video. Counts towards the approved revision; `output.srt` = subtitles as rendered (output timeline).
- **fit+mix** — place each VI segment at its absolute start, atempo to fit, pad silence; duck/replace original audio. Every TTS segment is first trimmed of its lead/tail silence (`tts.trim_files`, edge pads ~0.2 s + ~0.65 s; registry `tts/trimmed.json`, `VIZSUP_TRIM_TTS=0` off); `fit_estimate` models speech only at the project's real speed (`job_rate`) — 2026-10-30 this took eps 1–5 "QUÁ DÀI" 167 → 2.
- **Shorts (`pipeline/shorts.py`, `clipshort.py`, `canvas_text.py`, `safezones.py`)** — render page "Cài sẵn Short (9:16)" (learned per series): blur bars, captions above the platform's bottom strip, a second `canvas.ass` burned on the composed 9:16 frame (hook + chip in the top bar, "Xem full tập N" in the bottom bar, optional dialogue in the bottom bar); vertical sources get the safe-zone placement. Library ⋯ "Cắt Short" turns an APPROVED episode's 30–60 s range (heuristic or one AI proposal) into a NEW unapproved project reusing its TTS.
- **batch render ("Dựng hàng loạt", `pipeline/batch.py`)** — approved projects rendered one by one in the main window's SECOND worker slot, so the editor stays usable for the next episode. Sources: Thư viện → "Dựng hàng loạt" (only approved + not rendered since; settings copied from a rendered project) or the render page's "Dựng sau" (that page's settings; while a batch runs its primary button becomes "Thêm vào hàng dựng"). Every real render saves its settings to `render_opts.json` (older projects: rebuilt from render.json + voice.json + style.json); a queued project keeps its own style.json. The worker re-checks approval, so an episode edited after queueing is skipped; "Cần dựng lại" = the approved revision differs from the one `render.json` says was rendered (older renders: file times); the project being rendered can't be opened (the open one is locked while it renders).
- **compile ("Ghép tập", `pipeline/compilation.py`)** — series episodes are translated, reviewed and rendered one by one (each postable alone); Thư viện → "Ghép video" joins rendered projects, split videos or earlier compilations into one MP4 (folder with `compilation.json`, no job.json; never an editable project). Order by episode number in the title (第12集 / EP12 / Tập 12, editable), one chapter per episode (embedded + `chapters.txt` for YouTube), merged `vi.srt`. A compilation is a source again ("Tập 1–50" + 51…100) with its chapters kept. Stream copy when every file's parameters match INCLUDING codec headers (x264's PPS changes with CRF); else only the odd files are re-encoded to the majority's format with its encoder/preset (all of them if headers still differ), then concat-copy.
- **render** — dub track built in ≤5-min / ≤100-line windows (`dub/win_###.flac`, cached, sample-exact; the final encode has 2–3 inputs, `-progress` %, real cancel; NVENC when a test encode works — `VIZSUP_VIDEO_ENCODER=auto|nvenc|cpu`). FFmpeg burns styled `.ass` (bundled fonts via `fontsdir`); "Xem nhanh" 640p proof first; frame: source or TikTok 9:16 (bars = the picture blurred, or black — "Nền hai bên"); final mix loudnorm −14 LUFS / TP −1.5 so joined episodes match; translator watermark ("Mark" ASS style, faint, corner hops every 30 s, `disclosure.watermark_events`) — the creator's own watermark is kept, never removed; "Thẻ tập" = "Tập {n}" chip + "Còn tiếp · Tập {next}" end card from the title (`disclosure.episode_events`); a source a hair off 16:9 is snapped to the standard size so a series joins by stream copy; "Chất lượng" = resolution (short side, scaled BEFORE the burn, never upscaled) × preset Nhẹ/Cân bằng/Nét (CRF 27/23/20, NVENC CQ 30/25/21); cover "glass" = style "Kính mờ trắng" (`pipeline/glass.py`: per-line rounded mask .ass → blur + white tint over the Chinese band, dark text); exports: named MP4 copy, `.srt`/`.ass`, soft-sub `.mkv` (`pipeline/export.py`). Posting (`pipeline/disclosure.py`): optional burned corner notes for the first 5 s (source credit, "Lồng tiếng AI") as `Tag` events in the same `.ass`, a per-project rights note (`rights.json`, warns on unknown, never blocks), and a post-description + checklist dialog with "Gợi ý tiêu đề + hashtag (AI)" (`pipeline/postcopy.py`, one cheap "shorten"-role call).
- **autopilot (docs/plan/J-autopilot.md)** — the owner's loop is "paste a link (or let the watcher find it) → one-click approve". **watch** (`pipeline/watch.py`): followed pages per series (Bộ phim → Theo dõi, pre-filled with the newest downloaded episode); a Douyin **合集** (`douyin.com/collection/<id>` or any episode's link — its 合集 is looked up) is read whole through the page's own 合集 API (`douyin_capture --mix`) and is the surest: a creator page can leave public posts out (《末日校车》09, 2026-10-31); creator pages via the list mode (18–36 posts without login); Bilibili via yt-dlp (a 412 is retried once); a number inside the 《…》 name is never an episode → new episodes of the series run to the gate (the open app every 10 min when due, else `vizsup autopilot --once` from the Windows task `app/schedtask.py`, installed only by the owner's button). **Duyệt nhanh**: flagged lines only + one approve (auto-opens at the gate for an autopilot series) — the gate stays the owner's click. **`pipeline/autopilot.py`**: per-series plan (`_autopilot/plans.json`: platforms × long/Short, times, per day, auto Short, Vietnamese series name) → after approval the render is queued with the series' settings, the best heuristic Short is cut (approval carried ONLY if every line is an approved line, word for word), posts are planned (`_autopilot/posts.json`) and published at their slot (one process per post via `claim`; an unconnected platform gets a package in `storage/_posts`). **publishers** (`providers/publish/`, PublishProvider): YouTube (OAuth loopback + PKCE, resumable, playlist), Facebook Page videos + Reels (paste-login flow), TikTok (unaudited → private/inbox draft), folder; accounts in `storage/_accounts/` (never printed), Settings → «Đăng video», guide `docs/plan/J-publish-setup.md`. **Telegram remote** ("Điều khiển qua Telegram", `remote/telegram.py` + `pipeline/remote.py`, guide §6): the owner's own bot (token pasted, paired by a one-time `/start <code>`, every other chat ignored, secrets only in `_accounts/telegram.json`) — a link sent → run to the gate → the «Duyệt nhanh» content + [✅ Duyệt] (carries `approval.revision()[:8]`; refused when it changed / already approved / the job runs / the open editor's save changed it) → the same after-approve step; progress, plans, post results, `/trangthai`. App open: `desktop/remote_bridge.py` polls; app closed: `autopilot --once` answers and renders approved episodes headless (`pipeline/render.py`, the render body shared with the worker); one reader at a time (`_remote/poll.json`); the task repeats every 15 min once paired.
- **model catalog (`app/catalog.py`)** — `catalog/models.json` on the MAIN branch is fetched daily (and Settings → "Kiểm tra ngay"): role defaults / package overrides used only if valid and every model is live on OpenRouter; the user's MODEL_<ROLE> wins; also announces the latest app version. `VIZSUP_NO_UPDATE_CHECK=1` disables (tests set it).

## Hard constraints (learned from research — respect these)

- **Keep the human-edit gate AFTER translation and BEFORE TTS/render.** Never spend TTS credits or encode time on un-approved subtitles.
- **Providers are pluggable and UI-selectable.** Every translation/TTS/ASR/OCR engine implements the interface in `backend/app/providers/base.py` and registers in `registry.py`. Adding one = one file + register. Never hardcode a single provider in pipeline code.
- **ASR: timing ≠ accuracy.** One model writes the Chinese text (default: cloud Qwen-Omni via OpenRouter; FunASR Paraformer locally), Whisper only gives word timestamps. Don't use Whisper alone for Mandarin (CER 3–5× worse).
- **OCR: crop to the bottom third** before detection/recognition. Keep Google-Lens mode opt-in (it uploads frames).
- **Dub timing**: build VI audio on an **absolute timeline** with exact silence padding (no cumulative drift). Cap `atempo` at **~1.3×** (it skips samples above 2×); prefer shorter VI translations and `rubberband` over heavy speed-up.
- **Fonts**: subtitles need a **Vietnamese-diacritic Unicode font** (Be Vietnam Pro / Noto Sans). Use `BorderStyle=4` opaque box to cover leftover CN hardsubs.
- **Model ids**: the defaults live in `providers/roles.py` + `providers/presets.py`, and `catalog/models.json` (main) can override them — change models there, never in pipeline code. Verify any model id/pricing via https://openrouter.ai/api/v1/models — don't trust memory.
- **8GB VRAM**: run heavy models (WhisperX, FunASR, Demucs) **sequentially**, not concurrently.
- **Out of scope (v1)**: Kuaishou & Xiaohongshu download (no reliable OSS path); voice cloning (stock voice is enough).

## Layout

```
backend/app/          pipeline + providers + FastAPI (Python) — UI-agnostic core
  pipeline/           one module per stage
  providers/          base.py, registry.py, translation/, tts/, asr/, ocr/
desktop/              PySide6 (Qt) GUI — PRIMARY, built (calls app.* directly, no HTTP)
storage/              per-job working dirs (gitignored); _series/ (Bộ phim profiles), _cache/ (model catalog), _models/ (VAD)
samples/              test clips
docs/                 research, architecture, providers, dev-plan; docs/plan/ = active handbook
.claude/              skills, agents, settings
```

                               #   run: --series auto|SLUG|none --no-timing-pass --timing-scenes --no-vi-lint --voice-guess

## Conventions

- Python: type hints, `pathlib`, no global state in pipeline modules; each stage is a pure-ish function `stage(job: Job) -> Job` reading/writing the job dir.
- Subtitles in memory = a list of `Cue {index, start, end, text}` (see `pipeline/srt.py`). SRT/ASS are serialization formats only.
- Long work streams progress over WebSocket/SSE and checks a cancel flag between stages.
- Resilience: write sidecars with `app.fsutil.atomic_write_*` (temp + fsync + replace); renders/downloads write `*.rendering.mp4` / `source.downloading.mp4` and swap at the end; network stages go through `app.net.run_resilient` (waits for the network on connection errors only); the desktop keeps `storage/_session.json` and offers "Làm tiếp" after a crash or power loss.
- Match surrounding code style; keep provider files small and uniform.
